# 单文件失败隔离与继续取证

## 已确认故障

2026-10-28 21:56:53，Windows Application Error 指向 `pdfium.dll`，异常码 `0xc0000409`，API 被系统终止。该运行冻结 77 份文件，仅形成 4 个成功原生解析单元、1 个失败识别单元和 2 个未收敛识别单元。此故障不是业务隐患事实。普通 Python 异常也存在传播风险：批量工具原先用 `pool.map` 汇总，任一项抛异常便使整个批次响应失败；Pi 异常后宿主直接评估，缺少遗漏资料处理保障。

## 调整

- 每个 PDF 页面在独立短生命周期子进程中调用 PDFium。API 不加载 PDFium；同一宿主进程最多 2 个渲染子进程，默认每页总等待/运行上限 45 秒，超时 kill+wait 回收，原生崩溃转为页级失败。
- 文件/页面批次收集每个单元的结果，保留成功证据和失败原因；暂停、租约失效继续作为运行级中断，禁止过期执行者发布。
- 本地启动默认 `COMPLIANCE_HOST_COLLECTION_SWEEP=true`：宿主尝试每个冻结文件的原生解析，Pi 负责证据选择、跨文档取证和候选提交；Pi 返回或异常后，宿主在剩余时间及页数预算内补尝试未读页面，不重复请求已尝试的页。
- 日报、临界指标优先于后续处置资料补扫；达到预算时记录遗漏文件/页面数，不把未尝试标成检查成功。原生阶段最多使用总时长的一半，并预留后续模型与补扫时间；模型前按实际剩余时间给补扫预留约总时长 15%，原生阶段节余可用于模型，总任务时间不额外重置。
- 普通 PDF/Word/Excel 原生解析也可隔离到最多 4 个子进程，单文件默认 120 秒（裁剪到阶段剩余时限），超时与崩溃记录到对应文件。缓存与失败状态由宿主验证后保存。
- 文件结果区分业务问题、处理失败、未完成、候选待复核、识别未完整、待检索、未处理、已处理。成功文件默认收起，完整文件列表仍可查看处理状态。已解析不等于合规；OCR 成功仍是候选，不能越过事实验证。
- 历史已定版运行只生成只读解释，不覆盖结果、不自动回调或重跑。新策略及相关代码进入规则指纹，新任务使用新 executionId。

# 资料关系与事实冲突调整

## 评审决定

同报告日期、同资料类别允许存在多份附件。不同字节、同名、文件名“新/最新版”、上传或填报时间先后均不能证明业务事实冲突或替代关系。文件名日期仅保留为线索，不覆盖原始 report_time，也不单独改变 SQL 取数范围。

资料关系分为重复来源（同哈希）、并列资料、版本候选和事实冲突。只有独立验证的事实在同一事件、对象、精确时间、字段及适用条件下出现互斥值才形成事实冲突；模型候选、缺失值不作为反证。阈值比较需要同测点、方法、指标、等级和有效区间，先归一化单位。

文件名及可用逻辑资料键只用于版本候选提示。本阶段不自动选最新版，不自动作废任何来源。无法证明身份时正常保留多份资料，由已有事件/阈值适用性检查保留歧义，不能因为取消全局文件冲突而绕过必要命题或完整性门槛。

## 实施与验证计划

1. 先加入同类多附件、不同周验收记录、版本名称线索、真实互斥事实、单位换算、局部阻断及幂等回归测试。
2. 替换日期+类别的全局哈希冲突规则，复用冻结文件/证据/facts，不新增数据库和依赖；保留资料身份元数据。
3. 只隔离受影响命题及其必要依赖，保留无关已确证问题；结果、追问、页面列明文件、值、定位和原因。
4. 用现有真实冻结记录做离线只读对照，不触发模型/OCR、不更新历史账本。完成 Python、Node、Compose 和部署资产检查。

## 验收边界

多附件可共存；不同时间点的行动不视为矛盾；哈希相同不能计为独立佐证；版本候选不自动升级为冲突；相反事实必须可定位；缺证不可判未实施；任何 pass 仍须命题及覆盖完整。新策略进入 evaluator 指纹，只用于新 executionId。

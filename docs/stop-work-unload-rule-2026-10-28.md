# 冲击危险停工撤人与卸压：规则版本

本版本把检查项收敛到业务确认的六类资料和三步核查描述。它只影响新受理运行；已经冻结的旧运行继续使用原 `planRevision` 和历史结果。

## 六类资料

| 资料组 | 名称 | 频率 | 当前作用 |
| --- | --- | --- | --- |
| `prevention_daily` | 防冲工作日报表 | 日报 | 监测值、动力现象、事件时间和地点 |
| `threshold` | 冲击危险性预警临界指标 | 年报 | 指标、单位和有效的预警临界值 |
| `dispatch_daily` | 调度日报 | 日报 | 停止作业、断电、撤人和报告的实际记录 |
| `release` | 生产组织通知单 | 月报 | 指令层交叉记录，不能单独证明现场执行 |
| `relief_acceptance` | 防冲钻孔验收记录 | 周报 | 危险研判为真时，核对解危施工和验收 |
| `design` | 防冲设计 | 年报 | 核对解危方式和适用范围；不单独证明执行 |

`dispatch_daily` 在 `trigger=true` 后成为条件性资料，用于交叉核对实际处置时间和范围。`relief_acceptance` 和 `design` 则仅在监测预警已触发且同事件危险研判为真时，确定性 `warning_danger_confirmed=true` 才激活；该命题不是无预警时必须成立的业务命题。动力现象经危险研判虽进入四项处置核验，但不因此强制要求本轮卸压验收。阈值资料用于监测值触发分支；动力现象分支不因为没有阈值资料就自动缺证。不存在材料不等于明确没有执行，覆盖、来源不完整、不可读和冲突继续分别记录。

原始监测记录可作为《防冲工作日报表》的附件或页内原始记录，不创建第七类目录。危险研判也必须来自这六类中可追溯的实际记录；仅有模型解释、生产组织通知中的安排或没有研判材料，均不能假装已经研判。爆破解危若有施工及验收原件，也应随本轮六类受控资料绑定；当前六类目录尚未单列“爆破记录”，不能仅凭“防冲钻孔验收记录”标题推断已覆盖爆破施工。

`config/sources.example.json` 的 `file_name_id` 是目录映射示例，尚需与真实 OceanBase 文件类别 ID 对齐；配置存在不证明这些资料在某矿井、周期已完整到齐。

## OceanBase目录查询

新工程对 `mine_remote_disaster_file` 使用固定投影，不执行 `SELECT *`：

```sql
SELECT mine_code, mine_name, report_time, update_rate, cycle,
       file_name_id, file_name, attachment_id, attachment_name,
       CONCAT('https://172.26.10.67:8082/', local_bucket_name, '/', local_attachment_address) AS attachment_link,
       SUBSTRING_INDEX(local_attachment_address, '.', -1) AS suffix
FROM mine_remote_disaster_file
```

`mine_code`、六类 `file_name_id` 及周期条件使用绑定参数；周期过滤读取 `report_time_year/report_time_month`，年报只按年份，日报/周报/月报按任务月份，半年报按 `01/07`。结果中的 `attachment_link` 进入冻结下载流程，下载前仍检查 HTTPS 主机白名单、哈希和文件魔数。附件基址由来源配置控制，当前示例为 `https://172.26.10.67:8082/`；对象桶和对象键来自查询结果，不从任务报文接收。

本机已验证 OceanBase 连接和真实表字段，六类 ID 在2026年均有目录记录；尚未运行真实手动检查，因为当前 `.env.local` 尚未配置本项目的 OceanBase 模式、连接变量和附件服务下载策略。你在页面输入矿井/周期后，服务还需要使用对应的真实本地配置才会执行这条查询。

## 三步核查

1. 识别触发：从防冲工作日报表或监测原始记录提取监测值、指标名称、单位、预警临界值、时间和地点，判断是否超过冲击危险性预警临界指标。强烈震动、巨响、瞬间底（帮）鼓、煤岩弹射等动力现象，只有在同一事件有明确冲击地压危险研判时才进入处置核验。
2. 核对时序：按时间核对停止作业、切断电源、按避灾路线撤人、报告矿调度室；用调度日报和生产组织通知单交叉核对时间和范围。危险研判为真时，再核对钻孔卸压或爆破卸压的措施、范围、施工时间和验收结果。
3. 分层记录：触发、危险判定和未停工或未按措施撤人的事实有确证，记录疑似重大事故隐患，要求人工确认；危险研判为真且明确未解危、仍继续采掘时同样记录疑似重大事故隐患。只有明确未断电或未报告调度时，记录疑似违规。缺证、时间不清或冲突记录待补证/人工复核；证据完整无异常只表示本次事件未发现相应问题。

系统结果仍使用 `pass`、`no_pass`、`pending`、`unverifiable`、`failed`。疑似重大事故隐患和疑似违规是证据发现分类，不自动生成法定结论；模型候选不能直接产生这些分类。

新资产的`source.type`标明本次规则来自用户确认；历史工作簿的SHA256独立保存在`legacySource`，不冒充这次新规则文本的哈希。`assetRevision`与`planRevision`由项目编译时按资产字节生成。评价报告、人员记录、单独签字告知、限员设备等旧扩展条件不属于本版本六类资料的主链。
